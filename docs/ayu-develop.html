Design decisions

Decision Rationale Tradeoff Evidence
Split strategy engine, strategy context and plugin factories. Native engine feeds context state while callbacks stay behind strategy API. ABI, ownership and configured SDK compatibility must match deployment. WtCtaEngine (L22) / CtaStraContext (L23) / CtaStrategy (L26)
Choose replay scheduling from configured bar/tick/task inputs. Different strategy modes can reuse historical data replay. No subscribed main bar and disabled tick replay can end without processing data. run (L675)

Workflow

CTA quote to strategy callback

Actual CTA quote dispatch order. Replay/matching is a distinct inspected runtime path and is not asserted to call through live trader adapters. Configured parser/trader SDKs are integration boundaries.

Diagram source

  W1["on_tick calls base engine, updates data cache and executors."]
  W0 --> W1
  W2["Cache latest quote and adjusted historical ticks."]
  W1 --> W2
  W3["Dispatch subscribed context tick callback when ready, optionally through task pool."]
  W2 --> W3
  W4["Context invokes strategy.on_tick with current context."]
  W3 --> W4

  4. Dispatch subscribed context tick callback when ready, optionally through task pool.. on_tick (L475)

Strengths and limits

Strengths

  • Tick processing visibly updates base/data/executor state before subscribed strategy dispatch. on_tick (L475)

Limitations

  • Native SDK linking is platform dependent; recorded Linux tests do not prove macOS vendor adapters or live connectivity. docs/validation.md (L15)
  • Tick matching relies on modeled queue/trade/best-price rules; source presence does not establish complete exchange microstructure realism. handle_tick (L340)

Validation scope

The linked validation and command records preserve actual historical runs and user-authorized exclusions. This source/document review does not rerun application tests, establish live trading readiness or rank benchmark performance. Current data, credential and runtime prerequisites remain material.
